# 睡够就叫我 · SleepAfter

从**真正睡着的那一刻**开始计时的闹钟。你设"要睡 8 小时"，它不是从现在算，也不是从你上床算，而是从"手机判定你已经睡着"那一刻算。

假期、倒班、不规律作息专用：没有固定的起床时间，只有一个"睡够"的目标。

---

## 一、为什么不往手表里装

查过 Vela（小米/红米手表跑的系统）的真实能力后，有三个硬坑：

| 想做的事 | 实际情况 |
|---|---|
| 手表 App 读心率判入睡 | `@system.sensor` 在手环上**只实现了加速度、罗盘、气压**。心率、计步实测都是 `not a function` |
| 手表 App 整夜后台跑 | 快应用切后台会被**暂停**，只有 audio / record / request / geolocation 能申请后台，**传感器不在白名单** |
| 手表 App 自己设闹钟 | 三方快应用**没有系统闹钟权限**，只能 `vibrator` 自己震。被系统挂起 → 不震 → 睡过头 |

结论：手环适合当**传感器和震动器**，不适合当**闹钟的保证人**。闹钟必须由手机的系统闹钟通道兜底，因为 `AlarmManager.setAlarmClock()` 是唯一能绕过 Doze、到点必响的机制。

所以本项目的分工是：

- **手机**：判入睡 + 保证响（核心）
- **手表**：通过通知转发跟着震（白送，零代码）

## 二、工作原理

```
睡前点「开始守夜」
      │
      ├─ 前台服务 + 加速度计，滑动 30 秒窗口算"静止程度"（模长标准差）
      │
      ├─ 只有「熄屏 + 标准差 < 0.035」才累积静止时间
      │     └─ 亮屏即清零 → 躺床上刷手机不会被误判
      │
      ├─ 持续静止满 N 分钟（默认 8）→ 判定入睡，记下时刻
      │
      └─ 设闹钟：入睡时刻 + 目标时长，走 setAlarmClock
            │
            └─ 到点 → 高优先级通知 + fullScreenIntent 拉起全屏
                      → 最大音量 + 循环震动 + 必须长按才能关
```

关键设计：

- **不用定时器（Timer/Handler）**，用系统闹钟。App 进程被杀、手机重启（`BootReceiver` 会重挂）都不影响。
- **熄屏是必要条件**。熄屏在真实使用里几乎等价于"人不看屏幕了"，准确率远高于靠加速度硬猜。
- **最多守夜 3 小时**（`MAX_WATCH_MS`）。超过就放弃，绝不在半夜乱响。
- **有 Snooze**，且 Snooze 也是系统闹钟，不是内存定时器。

## 三、拿到 APK

仓库已配好 GitHub Actions，**不需要在本机装 Android Studio / SDK**。

1. 打开仓库的 **Actions** 标签页
2. 点最新的 `build-apk` 运行
3. 页面底部 **Artifacts** → 下载 `sleepafter-debug`
4. 解压得到 `app-debug.apk`，传到手机安装（允许"未知来源"）
5. 如果你想自己改代码：改完 push 到 `main`，Actions 会自动重新构建

想在本地构建：Gradle 8.7 + JDK 17 + Android SDK 34，`gradle assembleDebug`。

## 四、首次设置（很重要，缺一步就可能不响）

装完打开 App，按顺序点这三个：

1. **通知权限** → 允许（首次启动会弹）
2. **「打开精确闹钟权限」** → 系统设置里打开「闹钟和提醒」。这是 Android 12+ 的强制要求，不开就退化成不精确闹钟，可能晚几分钟
3. **「把本应用加入电池白名单」** → 允许忽略电池优化

国产 ROM（MIUI / HyperOS / ColorOS）还要额外做一步，否则后台服务会被清掉：

- 设置 → 应用管理 → 睡够就叫我 → **自启动** 打开、**省电策略** 改成「无限制」、**后台弹出界面** 允许

## 五、每晚怎么用

1. 手机**插上充电**，放床头或枕头边（要能感受到床的震动，加速度计才准）
2. 开 App，调目标时长（－15 / ＋15，范围 30 分钟 ~ 12 小时）
3. 点 **开始守夜**，锁屏放下
4. 睡。熄屏 + 静止 8 分钟后，状态会变成"已判定入睡 00:12 / 闹钟 07:42"
5. 到点响，**长按 3 秒**关掉；或点"再睡 9 分钟"

状态卡片会显示 **上次入睡潜伏期**（从你点"开始守夜"到判定入睡的分钟数）。这个数字才是真正值钱的东西——见第七节。

## 六、调参

都在 `SleepWatchService.kt` 顶部：

| 参数 | 默认 | 调法 |
|---|---|---|
| `STILL_SD` | `0.035` | 判定"静止"的加速度标准差阈值。**误判成入睡太快**（刚躺下就计时）→ 调小到 0.02；**一直判不出入睡** → 调到 0.05 |
| `WINDOW_MS` | `30000` | 滑动窗口。保持 30 秒即可 |
| `onsetStrictMinutes` | `8` | App 里点「静止 N 分钟算睡着」可循环切换 5/8/12/15/20 |
| `MAX_WATCH_MS` | 3 小时 | 守夜上限，超时静默放弃 |

**标定建议**：第一晚把 `STILL_SD` 放到 0.05，看 App 判定入睡的时刻和你实际感觉差多少，再往下收。

## 七、已知局限（先接受，再谈优化）

1. **手机必须在床上**。加速度计感知的是"手机动没动"，放桌上就没用了。
2. **同床的人翻身会影响判定**。轻微，但如果对方起夜，会让静止计时清零。
3. **深睡时翻身会重置计时**。所以严格判定（8 分钟）有时会让入睡时刻偏晚几分钟——偏晚是安全方向，宁可晚判也不早判。
4. **起床后的数据不能回传手环**。小米运动健康不开放写入，所以睡眠时长只在 App 里显示。
5. **国产 ROM 杀后台是最大风险**。第一晚建议先做一次"白天测试"：设 2 分钟目标、熄屏等 10 分钟，确认真的会响。

## 八、手表和手机是怎么联动的

**这一版没有"手机直接控制手表"的代码。** 联动走的是小米现成的路：

```
手机闹钟响 → 手机产生一条通知 → 小米运动健康把通知同步到手表 → 手表震
```

也就是**靠通知同步，不靠蓝牙直连**。所以在小米运动健康里要把"通知同步"打开。

⚠️ 这条链路**不保证一定生效**（不同固件行为不一样），第一次用之前必须单独试一次：
白天设一个 2 分钟后的闹钟，看手表震不震。**就算手表不震，手机闹钟本身照样响，不影响起床。**

如果实测确实不震，备选是装 Gadgetbridge（支持红米 Watch 6），它有 "Alarm clock alerts" 特性，专门在手机闹钟响时推给手表。

## 九、下一步可以做什么

- **把手表震动做进来**：Gadgetbridge 有 "Alarm clock alerts" 特性，手机闹钟响时会推给手表震动；或者用小米运动健康把通知转发到手表。零代码。
- **反向建议**：既然已经记了"入睡潜伏期"，就可以算"今晚该几点上床"——目标起床时间倒推，比改闹钟更不伤确定性。这也是苹果那份 `US10052061` 专利真正的思路。
- **手表端 .rpk**：等确认了红米 Watch 6 息屏后快应用到底能不能活着（这是唯一的未知），再考虑把"翻身检测"挪到手腕上——手腕永远在动，比手机准得多。
